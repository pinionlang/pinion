# Pinion AI 작성 비용 벤치마크 보고서

작성일: 2026-11-20 · 컴파일러 커밋: `5f3a86c` · 모델: `bedrock-claude-opus-5-5`

## 요약

- **정확성**: 새로 작성하는 과제와 기존 코드를 고치는 과제 모두에서 Pinion은 숨겨진 테스트를 **전부 통과**했다. Python, Go, TypeScript도 모두 통과했다.
- **코드 길이**: 새로 작성할 때 Pinion 소스는 Python보다 5% 길다. TypeScript보다는 12%, Go보다는 37% 짧다.
- **AI 비용**: Pinion은 **Python보다 비싸다.** 새로 작성할 때 가중 비용이 +32%, 기존 코드를 고칠 때 +50%다.
- **핵심 가설은 아직 입증하지 못했다.** "엄격한 검사와 명시적 효과가 AI의 수정 비용을 낮춘다"는 효과가 이번 측정에서는 나타나지 않았다. 두 언어 모두 빌드 오류가 거의 없어서 검사가 도움이 될 상황 자체가 없었다. 반면 낯선 언어의 비용(문서 읽기, 더 긴 코드)은 그대로 남았다.

## 1. 새로 작성: CRUD 백엔드 (언어마다 3회)

같은 명세를 언어마다 새 에이전트에게 구현시키고 숨겨진 블랙박스 테스트 74개로 채점했다.

| 언어 | 통과 | 소스 토큰 | 출력 토큰 | 캐시 읽기 | 가중 비용 | 도구 호출 | 문서 조회 | 빌드 오류 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| Python (FastAPI) | 74/74 ×3 | 1,243 | 3,353 | 77,671 | 48,027 | 3.7 | 0 | 0 |
| TypeScript | 74/74 ×3 | 1,474 | 4,035 | 89,090 | 53,304 | 4.0 | 0 | 1.0 |
| Go | 74/74 ×3 | 2,057 | 4,928 | 88,569 | 58,645 | 4.0 | 0 | 0 |
| **Pinion** | 74/74 ×3 | 1,302 | 4,415 | 169,303 | 63,504 | 6.0 | 2.0 | 0.3 |

Pinion 개선 이력(각 1회):

| 버전 | 바뀐 것 | 소스 토큰 | 가중 비용 |
|---|---|---:|---:|
| v1 | `std/http`만 있음. 에이전트가 JSON 파서를 직접 작성 | 3,724 | 155,073 |
| v2 | `json.Json` 동적 값 추가 | 1,578 | 83,111 |
| v3 | 참조 카드(약 3천 토큰), 검증 헬퍼, `Result` 핸들러 | 1,302 | 63,504 |

해석:
- Python보다 비싼 이유는 **문서 읽기**다. 차이의 약 60%가 문서 때문이다. 읽은 참조 카드가 맥락에 남아 매 턴 다시 읽히면서 캐시 읽기가 늘었다. 나머지는 출력 토큰이 31% 많은 데서 왔다.
- 빌드 오류는 Pinion이 평균 0.3회로 TypeScript(1.0회)보다 적었다.

## 2. 기존 코드 수정: 과제 5종 (Pinion과 Python, 각 1회)

같은 기준 코드에서 시작해 변경 요청서만 주고 고치게 했다. 채점은 변경된 동작과 기존 명세 전체의 회귀 검사를 함께 했다.

| 과제 | 내용 | 테스트 (Pinion / Python) | 변경 토큰 | 가중 비용 | 차이 |
|---|---|---|---:|---:|---:|
| T1 | 선택 필드 `isbn` 추가, 중복이면 409 | 117/117 · 117/117 | 537 / 276 | 68,615 / 55,079 | +25% |
| T2 | 저장 방식을 메모리에서 JSON 파일로 변경 | 109/109 · 109/109 | 313 / 248 | 57,727 / 37,558 | +54% |
| T3 | 증상만 적힌 버그 3개 수정 | 92/92 · 92/92 | 156 / 140 | 46,538 / 25,959 | +79% |
| T4 | 대여 상태와 상태 전이 추가 | 117/117 · 117/117 | 423 / 400 | 54,771 / 33,287 | +65% |
| T5 | 목록 응답을 `items`, `total` 형태로 변경 | 90/90 · 90/90 | 101 / 35 | 48,654 / 31,959 | +52% |
| **합계** | | | **1,530 / 1,099** | **276,303 / 183,843** | **+50%** |

해석:
- 두 언어 모두 **빌드 오류가 0건**이었다. Pinion 검사기가 잡아줄 실수가 없었다.
- Pinion은 모든 실행에서 참조 카드를 한 번씩 읽었다. 그 결과 캐시 읽기가 Python의 약 1.9배, 출력 토큰이 약 1.5~1.9배였다.
- T1과 T5에서 Pinion의 수정량이 2~3배였다. 원인은 **`data`를 JSON으로 바꿀 때 `None` 필드를 `null`로 쓰지 않고 생략하는 규칙**이다(설계 문서 3.7). 두 에이전트 모두 필드 타입을 `json.Json`으로 바꿔서 우회했다.

## 3. 측정하면서 발견해 고친 문제

| 문제 | 원인 | 조치 |
|---|---|---|
| 2·3회차 Pinion이 처음에 0점 | `pinion build -o`가 기존 실행 파일을 그 자리에서 덮어써서, macOS가 새 실행 파일을 즉시 종료시킴. 컴파일러 버그였음 | 임시 파일에 쓴 뒤 이름을 바꾸도록 수정(`13df10b`). 에이전트 소스는 그대로 두고 다시 채점해 74/74 |
| 세 에이전트가 모두 ID 카운터를 우회 패턴으로 작성 | 참조 카드의 예제 자체가 그 패턴이었음. AI가 예제를 거의 그대로 복사함 | 예제를 `class Store`의 `mut next_id` 방식으로 수정 |
| 평가기가 결과를 덮어씀 | 언어 하나만 다시 채점해도 결과 파일 전체를 다시 씀 | 채점마다 별도 원자료로 저장하고, 요약은 원자료에서 자동으로 생성 |
| 재현 정보를 기록하는 시점 | 문서 해시가 채점 시점에 기록됨 | 수정 과제부터는 에이전트 시작 시점에 기록(`start_run.py`) |

## 4. 측정 방법과 한계

- **가중 비용** = 입력×1 + 캐시 쓰기×1.25 + 캐시 읽기×0.1 + 출력×5. 입력 토큰 가격을 기준으로 한 상대값이고, 일반적인 가격 비율을 가정했다. 실제 청구액이 아니다.
- **도구 호출 분류**는 정규식으로 추정한 근사값이다. Bash 명령 하나가 여러 분류에 동시에 들어갈 수 있다.
- **표본이 작다.** 새로 작성은 언어마다 3회, 수정은 과제·언어마다 1회다. 수정 과제에서 Python이 5종 모두 이겼으므로 방향은 믿을 만하지만, 크기는 오차가 크다.
- HTTP 핸들러는 전역 잠금으로 하나씩 처리된다. 이번 결과로 처리량이나 동시성을 판단하면 안 된다.
- Python, Go, TypeScript의 실행 속도 비교는 별도 문서 `bench/results/RESULTS.md`에 있다.

## 5. 다음 단계 제안

1. **`None` 필드를 `null`로 쓰도록 규칙 변경**: 데이터가 직접 비용을 보여준 문제다. T1과 T5의 수정량이 줄어들 것으로 예상한다.
2. **실수가 생기는 과제로 측정**: 여러 모듈에 걸친 큰 코드베이스, 호출하는 곳이 많은 시그니처 변경, 복잡한 상태 전이. 검사기에 가치가 있다면 여기서 드러날 것이다.
3. **문서 비용 줄이기**: 참조 카드를 더 줄이거나, 핵심 규칙을 `pinion check`의 오류 메시지에 담아 문서를 읽지 않아도 되게 한다.
