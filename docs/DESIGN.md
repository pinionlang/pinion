# Pinion 설계 문서 (v0.5)

> **Pinion**: AI가 작성하고 디버깅하기 쉬운 객체 지향 언어

## 0. 핵심 가설

> 작은 언어 핵심, 명시적인 실패와 효과, 정확한 진단과 탐색 도구가 **AI의 작성·수정 비용을 실제로 낮추는가?**

v0는 이 가설을 검증할 만큼만 만든다. 엔터프라이즈 기능은 측정 결과를 보고 추가한다(8장).
규칙마다 정상·에러·경계 사례 예제를 [`spec/conformance/`](../spec/conformance/)에 둔다. 이 예제가 컴파일러 적합성 테스트이자 AI용 가이드의 원본이다.

## 2. 설계 원칙

1. **익숙한 문법**: Python, TypeScript, Kotlin, Rust와 비슷하게 만든다. 학습 데이터가 없으므로 이미 아는 토큰을 쓴다.
2. **정답이 하나**: 같은 일을 하는 방법은 하나만 둔다. 포매터를 강제한다.
3. **지역성**: 시그니처만 보고도 타입, 효과, 실패 가능성, **`self` 필드를 바꾸는지**를 알 수 있다. 다른 객체를 통한 간접 변경은 그 객체의 메서드 시그니처에서 드러난다(3.5).
4. **숨은 동작 없음**: 사용자 정의 데코레이터, 애너테이션, 매크로, 연산자 오버로딩, 암묵적 타입 변환을 두지 않는다. 허용하는 부분 타입 관계는 네 가지뿐이다: `T` → `T?`, 명시적으로 구현한 interface로의 변환, 효과 부분집합, `Never` → 모든 타입(3.15).
5. **보장은 구현한 범위까지만 약속한다**: 문서의 모든 보장 문구는 "무엇을, 어느 범위에서" 막는지 적는다.
6. **기계가 읽는 피드백**: 모든 진단을 버전이 붙은 JSON 스키마로 낼 수 있다(5장).
7. **작은 핵심 가이드**: 일상적인 작성에 필요한 **핵심 가이드는 3천 토큰 이하**로 둔다. 경계 조건까지 담은 **전체 레퍼런스는 따로 둔다.**

## 3. 의미 규칙 (v0)

### 3.1 바인딩과 최상위 선언

| 형태 | 의미 |
|---|---|
| `let x = ...` | 다시 대입할 수 없는 바인딩 |
| `var x = ...` | 다시 대입할 수 있는 **지역** 바인딩 |

- `let`은 재대입만 막는다. 객체 상태를 바꿀 수 있는지는 타입이 정한다(3.2).
- 모듈 최상위에 둘 수 있는 것: `fn`, `data`, `class`, `interface`, `enum`, `type`, `test`, 그리고 **깊은 불변(3.3) 타입의 `let` 상수**.
- 최상위 `let`의 초기값에는 효과가 없어야 한다. **최상위 `var`와 가변 전역 상태는 없다.** 그래서 테스트끼리 상태를 공유할 수 없고, 실행이 모듈 로드 순서에 좌우되지 않는다.

### 3.2 `data`와 `class`: 값과 참조

| | `data` | `class` |
|---|---|---|
| 용도 | 값, 메시지, DTO, 도메인 값 | 자원과 상태를 가진 서비스, 저장소, 핸들 |
| 의미 | **값**. 깊은 불변(3.3) | **참조**. 대입하면 별칭이 생긴다 |
| 필드 | **깊은 불변 타입만** (재귀 검사, `E1401`) | 무엇이든 |
| `mut` 필드, `mut fn` | 없음 | 있음 (3.5) |
| 생성 | 자동 생성자, `init` (3.6) | 자동 생성자, `init` (3.6) |
| `with` | 있음 (`init`을 거침) | 없음 |
| `==`, `Hash`, JSON | 필드 속성에 따라 자동 (3.3) | 없음 |
| 디버그 출력 | 있음 (3.8) | 있음 (3.8) |

```pinion
class Counter {
  mut count: Int = 0
  pub mut fn hit() { self.count += 1 }
  pub fn value() -> Int { self.count }
}

let c1 = Counter()
let c2 = c1            // 같은 객체를 가리키는 별칭
c2.hit()
assert c1.value() == 1 // class는 참조라서 c1에서도 보인다

data Snapshot {
  pub counters: List<Counter>   // E1401: Counter는 깊은 불변이 아니다
}
```

### 3.3 타입 속성

컴파일러는 타입마다 다음 여섯 속성을 **따로** 계산한다. 사용자가 이 속성을 직접 선언하는 문법은 없다.

| 속성 | 의미 | 쓰이는 곳 |
|---|---|---|
| **Frozen** (깊은 불변) | 그 값에서 도달할 수 있는 어떤 상태도 바뀌지 않는다 | `data` 필드, 최상위 `let`, (v0 이후) 작업 간 전달 |
| **Eq** | `==`, `!=` 사용 가능 | 비교, `Map` 키 |
| **Ord** | `<`, `>`, `sort` 사용 가능 | 정렬 |
| **Hash** | 해시 가능 | `Map` 키 |
| **Encode** | JSON으로 내보낼 수 있다 | `json.encode` |
| **Decode** | JSON에서 만들 수 있다 | `json.decode<T>` |

| 타입 | Frozen | Eq | Ord | Hash | Encode | Decode |
|---|---|---|---|---|---|---|
| `Int`, `Bool`, `Str` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `Float` (항상 유한, 3.15) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `()` | ✓ | ✓ | – | ✓ | – | – |
| `T?` | T | T | – | T | T | T |
| `List<T>` | T | T | T (사전순) | T | T | T |
| `Map<K, V>` (K는 항상 Eq+Hash) | K, V | V | – | V (순서 무관) | **K = `Str`**이고 V | **K = `Str`**이고 V |
| 튜플 `(A, B)` | 모두 | 모두 | 모두 (사전순) | 모두 | – | – |
| `Set<T>` (T는 항상 Eq+Hash) | T | ✓ (순서 무관) | – | ✓ (순서 무관) | T | T |
| `MutSet<T>` | – | – | – | – | – | – |
| `Dec` | ✓ | ✓ (수치 비교) | ✓ | ✓ | ✓ | ✓ |
| `Bytes` | ✓ | ✓ | ✓ (사전순) | ✓ | ✓ | ✓ |
| `Range` | ✓ | ✓ | – | ✓ | – | – |
| `Instant`, `Duration` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `Never` | (값이 없는 타입이라 속성을 따지지 않는다) ||||||
| `Result<T, E>` | T, E | T, E | – | T, E | – | – |
| `enum` | 모든 payload | 모든 payload | – | 모든 payload | 모든 payload | 모든 payload |
| `data` | **항상** (강제) | 모든 필드 | – | 모든 필드 | 모든 필드 | 모든 필드 **+ `init` 없음 + 비공개 필드 없음** |
| `class`, `MutList`, `MutMap`, `interface`, 함수 타입 | – | – | – | – | – | – |

("T"는 타입 인자가 그 속성을 가질 때만 성립한다는 뜻이다. "–"는 v0에서 제공하지 않는다는 뜻이다.)

규칙:
- `data`의 필드 타입은 재귀적으로 Frozen이어야 한다. 컬렉션, enum, 제네릭은 타입 인자와 payload까지 검사한다.
- **interface 타입은 Frozen이 아니다.** 구현체로 `class`가 올 수 있기 때문이다. 그래서 `data` 필드에 interface를 담을 수 없다.
- 제네릭 `data Box<T>`에서 `T`는 자동으로 Frozen을 요구받는다. `Box<Counter>`는 `E1402`다. 제네릭 `class`에는 이런 요구가 없다.
- enum은 payload에 `class`가 있어도 선언할 수 있다. 다만 그 enum은 Frozen이 아니므로 `data` 필드에 담을 수 없고, `==`도 쓸 수 없다.
- 속성이 없는 타입에 그 속성이 필요한 연산을 쓰면 에러다. 예: `class`에 `==`를 쓰면 `E1301`, Decode가 안 되는 타입에 `json.decode`를 쓰면 `E1501`.
- **`T??`(중첩 옵션)는 쓸 수 없다**(`E1204`). JSON의 `null` 하나로 두 단계의 "값 없음"을 구분할 수 없기 때문이다.

**재귀 타입의 속성**: 재귀 참조는 "그 속성을 가진다"고 가정하고 나머지 구성 요소로 판정한다(최대 고정점). 따라서 `enum Tree { Leaf, Node(left: Tree, right: Tree) }`는 나머지 구성 요소가 모두 Frozen이므로 Frozen이다.
- 값을 만들 수 없는 직접 재귀(`data A { pub a: A }`)는 `E1406`이다. 재귀는 `T?`, `List`, `Map`, enum 변형을 거쳐야 한다.
- 타입 인자가 바뀌는 재귀(`data Box<T> { pub inner: Box<List<T>>? }`)는 v0에서 금지한다(`E1407`). 속성 계산이 끝나지 않을 수 있기 때문이다.

### 3.4 컬렉션

| 타입 | 종류 | 설명 |
|---|---|---|
| `List<T>`, `Map<K, V>` | 불변 컬렉션 | 구조(원소 추가·삭제)는 바뀌지 않는다. **원소가 `class`이면 원소의 상태는 바뀔 수 있다.** 깊은 불변 여부는 3.3을 따른다 |
| `MutList<T>`, `MutMap<K, V>` | 가변 컬렉션 (참조) | `class`처럼 취급한다 |
| `.freeze()` | `Mut*`의 **구조를 복사해서 고정**한다 | 원소를 불변으로 바꾸지 않는다. `MutList<Counter>.freeze()`는 `List<Counter>`이고 Frozen이 아니다 |
| `xs[i]` | 범위를 벗어나면 결함 `R0102` | |
| `xs.get(i)` | `T?` | |

- `Map`과 `MutMap`의 순회 순서는 **삽입 순서**다. 재현성과 JSON 출력의 안정성을 위해서다.
- `Map`끼리의 `==`는 **순서와 무관**하다. 키 집합과 각 값이 같으면 같다.

```pinion
fn count_words(text: Str) -> Map<Str, Int> {
  let counts = MutMap<Str, Int>()
  for w in text.words() {
    counts.set(w, (counts.get(w) ?? 0) + 1)
  }
  counts.freeze()
}
```

### 3.4.1 컬렉션 보조 메서드

흔한 집계·변형을 한 호출로 쓰게 해서 `MutMap`·`MutList`와 반복문을 덜 쓰게 한다. 전체 목록은 STDLIB.md에 있다.

- 불변 결과: `count_by`, `group_by`(키는 처음 나온 순서), `take`, `drop`(범위를 넘으면 잘라 냄, 음수는 `R0102`), `max_by`·`min_by`(같으면 **처음** 원소, 빈 리스트면 `None`), `sum_by`, `index_of`, `distinct`(처음 나온 순서), `Map`의 `get_or`, `map_values`, `filter(fn(K, V) -> Bool)`. `Range`는 `List<Int>`의 조회·고차 함수를 그대로 가지며 결과는 `List`다: `(0..n).map(i => ...)`.
- 가변: `MutMap.inc(k)`(값이 `Int`인 맵만, 없으면 1을 넣음), `MutMap.update(k, default, f)`, `MutList.remove_at(i)`(범위 밖 `R0102`), `insert(i, x)`, `retain(f)`.
- 콜백 보장은 3.12와 같다: **원소마다 한 번, 순서대로** 부른다(`update`는 한 번). 콜백 안에서 같은 컬렉션을 바꾸면 `R0107`이다.
- `sort_by`·`max_by`·`min_by`의 키는 Ord이며 튜플 키는 사전순이다: `sort_by(e => (-e.count, e.word))`.

```pinion
let counts = text.words().count_by(w => w)
let top = counts.keys().sort_by(w => (-counts.get_or(w, 0), w)).take(10)
```

### 3.5 `mut`의 정확한 의미

> **`mut fn`은 수신 객체(`self`)의 필드에 직접 대입하거나, `self`에 대해 다른 `mut fn`을 호출할 수 있는 메서드다.**
> **`mut`가 없는 함수도 다른 참조 객체의 상태는 바꿀 수 있다.**

| 코드 | `mut fn`이 아닌 메서드 안에서 |
|---|---|
| `self.count = 1` | `E3101` |
| `self.hit()` (`hit`이 `mut fn`) | **`E3103`**. 보조 메서드로 `mut` 표시를 우회하지 못하게 한다 |
| `self` 안에서 정의한 클로저가 `self.hit()`을 호출 | `E3103`. 클로저 본문도 해당 메서드의 일부로 검사한다 |
| `self.counter.hit()` (필드에 담긴 다른 객체) | 허용. 그 변경은 `Counter.hit`의 시그니처에 드러난다 |
| `helper(self)`처럼 `self`를 다른 함수에 넘김 | 허용. **넘겨받은 함수가 `self`를 바꿀 수 있다.** 이것이 얕은 규칙의 한계이며, 레퍼런스에 명시한다 |

- `mut`도 없고 효과도 없다고 해서 **순수 함수는 아니다.** 인자로 받은 참조 객체를 바꿀 수 있기 때문이다. v0는 순수성을 보장하지 않는다.
- `data`에는 `mut`가 없으므로 위 규칙은 `class`에만 적용된다.

**필드 대입 규칙**:
- `mut`가 붙지 않은 필드는 생성 이후 대입할 수 없다. `mut fn` 안에서도 마찬가지다(`E3104`). 이런 필드는 생성자나 `init`의 `Self { }`에서만 값을 정한다.
- **필드 대입은 그 클래스 자신의 `mut fn` 안에서 `self.필드 = ...` 형태로만** 할 수 있다(`E3105`). 그래서 직접 대입은 항상 어떤 `mut fn` 시그니처를 거친다. 구체적으로 다음은 모두 `E3105`다.
  - 바깥에서 다른 객체의 필드에 대입: `c.count = 1` (`pub mut` 필드라도 금지)
  - 자기 `mut fn` 안에서 별칭을 거친 대입: `let alias = self` 후 `alias.count = 1`
  - 자기 `mut fn` 안에서 필드 객체의 필드에 대입: `self.child.count = 1` (`child`의 `mut fn`을 불러야 한다)
- **`pub`과 `mut`의 역할**: `pub`은 다른 모듈에서 **읽기**를 허용하고, `mut`는 그 클래스 **내부에서 대입**을 허용한다. `pub mut`는 "외부에서 쓸 수 있다"는 뜻이 아니다.
- 여기서 "읽기 전용"은 **필드에 직접 대입하지 못한다**는 뜻일 뿐이다. `pub` 필드가 참조 객체이면 `c.child.hit()`처럼 그 객체의 `mut fn`을 불러 내부 상태를 바꿀 수 있다(얕은 규칙, 위 표).

### 3.6 생성: `init`, `Self { }`, `with`, 팩토리, 역직렬화

**원칙: 값을 만드는 모든 경로가 같은 검증을 거친다.**

| 경로 | `init`이 있을 때 |
|---|---|
| 자동 생성자 `T(...)` | `init`을 거친다 |
| `v.with(...)` (`data`만) | 바뀐 필드를 반영한 값으로 `init`을 거친다 |
| `json.decode<T>` | **v0에서는 허용하지 않는다** (`E1501`). 공개 DTO로 디코드한 뒤 생성자나 팩토리로 바꾼다 |

`init` 규칙:
- **`data`의 `init` 매개변수는 저장 필드와 정확히 같아야 한다**(이름, 타입, 순서). 그래야 `with`가 현재 필드 값으로 `init`을 다시 부를 수 있다(`E1503`). 다른 형태의 입력으로 만들고 싶으면 **이름 있는 팩토리 함수**를 쓴다.
- `class`의 `init`은 매개변수를 자유롭게 정할 수 있다. `class`에는 `with`와 역직렬화가 없기 때문이다.
- `init`은 `Self`나 `Result<Self, E>`를 돌려준다. `Result`이면 생성자와 `with`도 `Result`를 돌려준다.
- **내부 생성 `Self { field: v, ... }`는 `init` 안에서만** 쓸 수 있다(`E1504`). 모든 필드를 채워야 한다(`E1505`). `init` 안에서 `T(...)`를 부르면 `init`을 재귀 호출하게 되므로 쓰지 않는다.

효과와 평가 순서:
- **필드 기본값 식에는 효과가 없어야 한다**(`E3005`).
- **`data`의 `init`에는 효과가 없어야 한다**(`E3006`). 그래야 생성자와 `with`가 항상 효과 없는 연산으로 남는다.
- `class`의 `init`은 효과를 선언할 수 있다(`init(dir: Str) -> Self !fs`). **그 효과는 생성자 호출식에 전파되므로**, `Store(dir: d)`를 부르는 함수도 `!fs`를 선언해야 한다.
- 생성자 호출은 ① 넘긴 인자를 작성 순서대로 평가하고 ② 생략된 필드를 선언 순서대로 기본값으로 채운 뒤 ③ `init`을 실행한다. `init`이 없으면 ③ 대신 그 값으로 바로 필드를 채운다.

```pinion
data Account {
  pub id: Int
  balance: Int

  init(id: Int, balance: Int) -> Result<Self, AccountError> {
    if balance < 0 { return Err(AccountError.Negative(balance)) }
    Ok(Self { id: id, balance: balance })
  }

  pub fn withdraw(amount: Int) -> Result<Account, AccountError> {
    if amount <= 0 { return Err(AccountError.InvalidAmount(amount)) }
    if amount > self.balance { return Err(AccountError.Insufficient(self.balance)) }
    self.with(balance: self.balance - amount)
  }
}

pub fn open_account(id: Int) -> Result<Account, AccountError> {   // 팩토리
  Account(id: id, balance: 0)
}
```

가시성 규칙(3.17 모듈 기준):
- 비공개 필드가 있는 타입은 **모듈 밖에서 자동 생성자와 `with`를 쓸 수 없다.** 모듈이 제공하는 `pub fn`으로 만든다.
- 비공개 필드가 있거나 `init`이 있는 `data`는 Decode 속성이 없다. 범용 디코더가 필드를 직접 채워서 검증을 우회하는 경로를 막기 위해서다.

### 3.7 JSON 매핑

**매핑 규칙은 명세로 고정한다. 타입 정의를 바꿀 때 생기는 JSON 호환성(필드 이름 변경, 필드 추가)은 사용자가 따로 관리한다.**

| Pinion | JSON |
|---|---|
| `Int` | 정수. 디코드할 때 소수점이 있거나 64비트 범위를 넘으면 에러 |
| `Float` | 숫자 |
| `Str`, `Bool` | 문자열, 불리언 |
| `List<T>` | 배열 |
| `Map<Str, V>` | 객체 (삽입 순서로 출력) |
| `Set<T>` | 배열 (삽입 순서로 출력). 디코드할 때 중복 원소가 있으면 에러(`duplicate_element`) |
| `Dec` | **문자열** (`"12.30"`). 자릿수(scale)를 보존한다. 숫자로 쓰면 이진 부동소수점으로 읽힐 위험이 있어서다. 디코드는 문자열만 받는다 |
| `Bytes` | 표준 base64 문자열 |
| `Instant` | RFC 3339 UTC 문자열 (`"2026-11-20T09:30:00.123456789Z"`) |
| `Duration` | 정수 나노초 |
| `data` | 객체. **모든 필드**를 선언된 이름 그대로 출력한다. 비공개는 접근 제어일 뿐 출력 제외가 아니다. 숨길 필드가 있으면 DTO를 따로 만든다 |
| `enum` | **인접 태그 형식**. payload를 `value` 안에 넣으므로 payload 필드 이름과 판별자가 충돌하지 않는다. 예약 필드 이름도 없다.<br>이름 있는 payload: `{"tag": "Member", "value": {"team": "core"}}`<br>위치 payload: `{"tag": "Code", "value": [42]}`<br>payload 없음: `{"tag": "Admin"}` |

**`T?`의 `None`은 위치에 따라 다르게 표현한다.**

| 위치 | 인코드 | 디코드 |
|---|---|---|
| **객체 필드** (`data` 필드, enum의 이름 있는 payload 필드) | 필드를 **생략** | 필드가 없거나 `null`이면 `None` |
| 배열 원소 (`List<Int?>`) | `null` | `null`이면 `None` |
| **`Map` 값** (`Map<Str, Int?>`) | `null`. **키를 지우지 않는다.** 인코드 후 디코드해도 키가 남는다 | `null`이면 `None`. 키가 없으면 그 키가 없는 것 |
| 최상위 값, 위치 payload | `null` | `null`이면 `None` |

디코드 규칙: 모르는 필드, 빠진 필수 필드, 중복 키, 타입 불일치는 모두 에러다. 결과는 `Result<T, JsonError>`이고, `JsonError`는 경로(`$.items[2].name`)와 종류를 담는다.

### 3.8 디버그 표현

- JSON과 **별개의 계약**이다. 형식이 안정적이라고 보장하지 않는다.
- 깊이 4, 컬렉션 원소 20개까지만 표시하고 `…(+N)`으로 생략을 표시한다. 순환 참조는 `<cycle #id>`, 클로저는 `<fn (Int) -> Str>`로 표시한다.
- 런타임 진단에서 값을 언제 캡처하는지는 5장을 따른다.

### 3.9 interface

- 구현은 명시한다: `class SqlRepo : Repo`. `data`도 interface를 구현할 수 있다.
- 구현 타입의 값은 그 interface 타입 자리에 쓸 수 있다(3.15). **구현을 선언하지 않은 타입은 메서드가 모두 맞아도 쓸 수 없다**(구조적 타이핑 없음).
- interface 값을 구현 타입으로 되돌리는 변환(다운캐스트, `is`, `as`)은 없다. 종류별로 다르게 처리해야 하면 enum을 쓴다.
- v0에는 기본 메서드가 없다.
- 호환 규칙:
  - 구현 메서드의 효과는 interface 메서드에 선언된 효과의 부분집합이어야 한다.
  - interface 메서드가 `mut fn`이 아니면 구현도 `mut fn`일 수 없다.
  - 인자 타입과 반환 타입은 정확히 같아야 한다.

### 3.10 enum과 match

- 생성식에서는 변형을 **타입 이름과 함께** 쓴다: `OrderState.Paid(items, p)`. 예외는 기본 제공되는 `Ok`, `Err`, `Some`, `None`뿐이다.
- 패턴에서는 대상 타입이 정해져 있으므로 변형 이름만 쓴다: `Paid(items, p) => ...`
- `match`는 완전해야 한다(`E2001`). 중첩 패턴을 포함해 재귀적으로 검사한다.
- **가드**(`Paid(p) if p.total > 0 =>`)가 붙은 갈래는 완전성 계산에 포함하지 않는다.
- **`A(x) | B(x)` 패턴은 양쪽이 같은 이름을 같은 타입으로 묶어야 한다**(`E2003`).
- **와일드카드 규칙** (의도적인 절충이다):
  - 대상이 enum 하나일 때 **갈래 전체가 `_`이거나 바인딩 하나(`other =>`)인 패턴은 금지**한다(`E2002`). payload 안쪽의 `_`(`Paid(_, _)`)는 허용한다.
  - 튜플 등 여러 값을 조합할 때는 `_`를 허용한다.
  - **이 규칙은 완전한 변경 감지가 아니다.** 튜플의 `_`는 새로 추가된 변형도 흡수한다. `match (state, true)`처럼 감싸면 규칙을 피할 수도 있다.
  - 보완책: `pinion outline`과 진단이 각 `_`가 흡수하는 조합을 **패턴으로 압축해서** 보여준다(예: `_ ⊇ (Shipped | Cancelled, _)`).

### 3.11 실패: 업무 실패와 프로그램 결함

| 구분 | 예 | 표현 |
|---|---|---|
| **업무 실패** | 사용자 없음, 잔액 부족, 파일 없음, 파싱 실패 | `Result<T, E>`, `T?` |
| **프로그램 결함** | 인덱스 범위 초과, 정수 오버플로, 0으로 나누기, Float가 유한하지 않음, 테스트 밖에서 실패한 `assert` | **중단(abort)** |

- `?`는 `Result`에만 쓴다. `T?`는 `let x = opt else { ... }`나 `opt ?? 기본값`으로 처리한다.
- `let ... else`와 `??`는 `T?`에만 쓴다. `Result`의 오류를 버리고 `T?`로 다루려면 `.ok()`를 명시한다: `fs.read(p).ok() ?? ""`.
- 성공값을 자동으로 `Ok`로 감싸지 않는다. 오류 타입도 자동으로 변환하지 않는다(`.map_err(AppError.Db)`).
- 반환된 `Result`를 쓰지 않으면 `E2101`이다. 의도적으로 버릴 때는 `let _ = ...`로 쓴다.
- 결함이 나면 v0(CLI)에서는 프로세스 전체를 종료하고 종료 코드 70을 낸다. 테스트 실행 중에는 5.3을 따른다.
- `main`은 `Result<(), E>`를 반환할 수 있다. `Err`이면 오류를 출력하고 종료 코드 1을 낸다.

```pinion
class UserService {
  repo: Repo

  pub fn rename(id: Int, name: Str) -> Result<User, AppError> !db {
    let found = self.repo.find(id).map_err(AppError.Db)?
    let u = found else return Err(AppError.NotFound(id))
    self.repo.save(u.with(name: name)).map_err(AppError.Db)
  }
}
```

(`!db`는 v0 이후 기능이다. 실패 규칙을 보여주려고 썼다.)

### 3.12 평가 순서

v0는 모든 식을 **즉시, 순차로, 왼쪽에서 오른쪽으로** 평가한다.

- 함수 인자, 이항 연산의 피연산자, 튜플과 리스트 리터럴은 왼쪽에서 오른쪽으로 평가한다.
- 메서드 호출은 수신 객체를 먼저 평가하고, 그다음 인자를 평가한다.
- 이름 붙은 인자는 **작성한 순서대로** 평가한다(선언 순서가 아니다).
- `&&`, `||`, `??`는 단락 평가한다.
- 표준 고차 함수는 모두 즉시 실행된다. 지연 시퀀스는 v0에 없다. 콜백 호출 보장은 함수 종류에 따라 다르다.

| 함수 | 콜백 호출 보장 |
|---|---|
| `map`, `filter`, `each`, `fold` | 앞에서부터 순서대로, **원소마다 정확히 한 번** |
| `any`, `all`, `find` | 앞에서부터 순서대로 호출하고, **결과가 정해지는 원소에서 멈춘다**(원소마다 최대 한 번) |
| `sort_by(key)` | **키 추출 방식**이다. 원래 순서대로 원소마다 키를 정확히 한 번 계산한 뒤 정렬한다. **안정 정렬**이라서 키가 같은 원소는 원래 순서를 유지한다. 키 타입은 Ord여야 한다 |
| `sort()` | 원소 타입이 Ord여야 한다. 안정 정렬 |

비교 함수를 받는 정렬은 v0에 없다.
- 콜백에서 결함이 나면 그 자리에서 중단한다. 이미 실행된 효과는 되돌리지 않는다.
- `??`를 산술·비교 연산자와 괄호 없이 섞으면 `E0102`다. `(a ?? 0) + 1`로 쓴다.

### 3.13 효과

효과의 역할은 **무엇을 사용하는지 표시하고 검사하는 것** 하나다.

| 역할 | 장치 | 시기 |
|---|---|---|
| 무엇을 사용하는지 표시 | 효과 + 컴파일러 검사 | v0 |
| 구체적으로 무엇에 접근할 수 있는지 제한 | capability (런타임이 강제) | v0 이후 |
| 같은 실행을 재현 | 효과 대체 | v0는 **통제한 효과 아래에서 재현 가능한 테스트**까지만 약속한다 |

v0 효과는 `!io`(표준 입출력), `!fs`, `!env`(인자·환경변수), `!time`, `!rand`, `!net`(네트워크 서버, 3.21)이다. 포함 관계가 없는 평면 구조다.

규칙:
1. 이름 있는 함수와 메서드는 효과를 명시한다. 본문에서 쓰는데 선언하지 않으면 `E3001`, 선언했는데 쓰지 않으면 경고 `W3002`다.
2. 클로저의 효과는 추론한다. 함수 타입은 효과를 포함한다: `fn(Str) -> Int !fs`.
3. **함수 값의 호환성**: 실제 함수의 효과가 요구된 효과의 부분집합이면 넘길 수 있다. 효과가 없는 콜백을 `fn(Int) -> Int !io` 매개변수에 넘길 수 있다.
4. 효과 다형성은 없다. 그래서 `apply(f: fn(Int) -> Int !io) -> Int !io`를 호출하는 식은 순수한 콜백을 넘겨도 **정적으로 `!io`를 가진다.**
5. 표준 고차 함수는 예외적으로 콜백의 효과를 그대로 전달한다(컴파일러 내장 규칙).
6. interface 구현의 효과는 3.9를 따른다.
7. **`main`에 선언된 효과는 `main`을 통해 실행되는 코드의 정적 효과 상한**이다. 권한이 아니다.
8. 효과는 비동기와 무관하다.

9. **테스트는 기본적으로 밀폐된다.** `test` 블록 안에서는 모든 표준 효과가 기본 가짜 구현으로 바뀐다.

| 효과 | 테스트 기본값 |
|---|---|
| `io` | 출력을 캡처한다. 실패한 테스트의 결과에 붙여서 보여준다. 입력은 비어 있다 |
| `fs` | 빈 가상 파일 시스템 |
| `env` | 빈 인자, 빈 환경변수 |
| `time` | 고정 시각 `2000-01-01T00:00:00Z`. 대기는 즉시 끝나고 시각만 진행한다 |
| `rand` | 고정 시드 |
| `net` | 네트워크 없음. `app.listen`은 결함 `R0109`. 라우팅은 `app.handle(http.request(...))`로 시험한다 |

   - 실제 효과가 필요한 테스트는 `test "실제 설정 파일 읽기" !fs { ... }`처럼 **선언한 효과만 실제 구현으로 실행**한다. 선언하고 쓰지 않으면 `W3002`다.
   - **같은 `!fs` 표기가 두 가지 역할을 한다.** 함수와 메서드의 `!fs`는 "이 코드가 파일 시스템을 **사용한다**"는 표시다. 테스트의 `!fs`는 "이 테스트에서는 파일 시스템에 **실제 구현을 쓴다**"는 선택이다. 핵심 가이드에 이 차이를 따로 설명한다.
   - 보장 범위: 효과를 선언하지 않은 테스트는 **표준 효과를 통한 외부 입력(파일, 환경변수, 인자, 표준 입력, 시각, 난수)을 통제한다.** 실행 시간 제한, 운영체제와 플랫폼의 차이, 메모리 같은 실행 환경 차이까지 없애지는 않는다.

**효과 대체** (`with fs: fs.fake(...) { ... }`):
- **`test` 블록 안에서만** 쓸 수 있다(`E3201`).
- 블록 안에서 **직접이든 간접이든** 호출된 모든 코드에 적용된다.
- 중첩되면 가장 안쪽 대체가 우선한다.
- 블록을 벗어나면 정상 종료든 결함이든 반드시 바깥 구현으로 돌아간다. 바깥 구현은 테스트 기본 가짜이거나, 테스트에 선언한 실제 구현이다.
- v0에서 대체할 수 있는 것은 표준 효과(`io`, `fs`, `env`, `time`, `rand`)의 표준 가짜 구현뿐이다. 사용자 정의 효과 핸들러는 없다.

### 3.14 제네릭

- 제네릭 함수와 제네릭 `data`·`class`를 허용한다.
- 사용자가 쓸 수 있는 제약은 `Eq`, `Ord`, `Hash`뿐이다. `data`의 타입 매개변수에는 Frozen 요구가 자동으로 붙는다(3.3).

### 3.15 숫자, 연산자, 부분 타입

- `Int`는 64비트이고 오버플로를 검사한다(`R0101`). 정수 0으로 나누기는 `R0103`이다.
- **`Float`는 항상 유한하다.** NaN이나 무한대를 만드는 연산은 결함 `R0104`다. 그래서 `Float`도 Eq, Ord, Hash를 문제없이 만족한다. `-0.0`과 `0.0`은 같고 해시도 같다. NaN이 필요한 수치 계산용 타입은 v0 이후에 검토한다.
- `Int`와 `Float`를 섞어 연산하면 에러다. 변환은 `x.to_float()`처럼 명시한다.
- 사용자 정의 연산자 오버로딩은 없다. 산술 연산자는 내장 숫자 타입과 그 별칭(`type Cents = Int`)에만 쓸 수 있다.
- 부분 타입 관계는 네 가지뿐이다.

| 관계 | 예 |
|---|---|
| `T`는 `T?` 자리에 쓸 수 있다 | `email: "a@b.c"` |
| **명시적으로 구현한 interface 자리에 구현 타입의 값을 쓸 수 있다** | `Coupon : Discount`이면 `Coupon` 값을 `Discount` 인자, 반환값, 필드, 리스트 리터럴 원소로 쓸 수 있다 |
| 효과가 더 적은 함수는 효과가 더 많은 함수 타입 자리에 쓸 수 있다 | 순수 콜백을 `fn(Int) -> Int !io` 자리에 넘기기 |
| `Never`는 모든 타입 자리에 쓸 수 있다 | `let x = opt else return`, match 갈래의 `todo()` |

- 이 관계는 **값 하나**에만 적용된다. 위 두 관계는 함께 쓸 수 있다(`Coupon` → `Discount?`).
- **제네릭 타입에는 변성이 없다.** `List<Coupon>`은 `List<Discount>` 자리에 쓸 수 없다(`E1201`). 변환은 `coupons.map(c => c)`처럼 명시한다. 기대 타입이 `List<Discount>`이면 클로저 반환값에 위의 값 변환이 적용된다. 이렇게 하면 원소 수만큼 비용이 든다는 것도 코드에 드러난다.
- 함수 타입의 인자와 반환 타입에도 변성이 없다. 효과만 예외다.

### 3.15.1 문자열

- `Str`은 **항상 올바른 UTF-8**이다. 파일 내용이 올바른 UTF-8이 아니면 `fs.read`가 `Err(FsError.InvalidUtf8)`을 돌려준다.
- **길이와 인덱스의 단위는 유니코드 코드 포인트**다. `"한글".len()`은 2다. 바이트 수는 `byte_len()`으로 따로 얻는다. 진단의 열 번호도 같은 단위를 쓴다.
- `s.slice(start, end)`도 코드 포인트 단위다. 범위를 벗어나면 결함 `R0102`다. `s[i]` 인덱싱은 없다.
- 사람이 보는 "글자"(grapheme cluster, 예: 결합 문자, 이모지 조합)는 v0에서 다루지 않는다.
- `s.lines()`는 `"\n"`으로 나누고, 각 줄 끝의 `"\r"` 하나를 지운다. 문자열 끝의 `"\n"` 뒤에는 빈 줄을 만들지 않는다.
- `s.words()`는 유니코드 공백 문자로 나누고 빈 조각은 버린다.

### 3.15.2 추가 자료형

#### `Never`

- 값이 하나도 없는 타입이다. **끝까지 실행되지 않는 식**의 타입이다: `return`, `break`, `continue`, `todo()`, `unreachable()`.
- `Never`는 모든 타입 자리에 쓸 수 있다. 그래서 `let u = found else return Err(...)`, `x => todo()`가 타입 검사를 통과한다.
- `todo()`는 실행되면 결함 `R0105`로 중단한다. `unreachable()`은 `R0106`이다. 둘 다 메시지 인자를 받을 수 있다: `todo("환불 처리")`.
- 사용자가 `Never`를 반환 타입으로 직접 쓸 수 있다: `fn fail(msg: Str) -> Never { unreachable(msg) }`.

#### `Range`

- `a..b`는 `a` 이상 `b` 미만, `a..=b`는 `a` 이상 `b` 이하다. **정수(`Int`)만** 쓸 수 있다.
- `a >= b`인 `a..b`는 빈 범위다(에러가 아니다). 거꾸로 셀 때는 `(0..n).rev()`, 간격은 `(0..10).step(2)`를 쓴다. `step`에 0 이하를 주면 결함 `R0102`다.
- `Range`는 값이다(Frozen, Eq, Hash). 리스트를 만들지 않고 순회한다. 리스트가 필요하면 `.to_list()`를 쓴다.
- `for`로 순회할 수 있는 것: `List`, `MutList`, `Set`, `MutSet`, `Map`·`MutMap`(`(키, 값)` 튜플), `Range`, `Bytes`(각 바이트 `Int`). 문자열은 `s.chars()`(코드 포인트 하나씩 담은 `List<Str>`)로 순회한다.
- **순회 중인 가변 컬렉션을 바꾸면 결함 `R0107`이다.** 순서가 정해지지 않는 동작을 막기 위해서다.

#### `Set<T>`, `MutSet<T>`

| 항목 | 규칙 |
|---|---|
| 중복 판정 | 원소 타입은 **항상 Eq + Hash**여야 한다(`E1207`). 두 원소가 `==`이면 같은 원소다. Float의 `-0.0`과 `0.0`은 같은 원소다 |
| 순회 순서 | **삽입 순서**. 이미 있는 원소를 다시 넣으면 순서는 처음 위치 그대로다. 지웠다가 다시 넣으면 맨 뒤로 간다 |
| 비교 | `==`는 순서와 무관하다. 원소 집합이 같으면 같다. 해시도 순서와 무관하다. Ord는 없다 |
| 생성 | 리터럴은 없다(`{}`는 `Map`이다). `Set([1, 2, 2])`(중복은 버림, 첫 등장 순서 유지), `xs.to_set()`, `MutSet<Int>()` |
| 조회 | `s.contains(x)`, `s.len()`, `s.is_empty()`, `a.is_subset(b)`, `a.is_disjoint(b)` |
| 집합 연산 (`Set`) | 새 `Set`을 돌려준다. 결과의 순서도 정한다 |
| | `a.union(b)`: `a`의 원소를 `a` 순서대로, 그다음 `a`에 없는 `b`의 원소를 `b` 순서대로 |
| | `a.intersect(b)`: `b`에도 있는 `a`의 원소를 `a` 순서대로 |
| | `a.diff(b)`: `b`에 없는 `a`의 원소를 `a` 순서대로 |
| | `a.sym_diff(b)`: `a.diff(b)` 다음에 `b.diff(a)` |
| 변경 (`MutSet`) | `s.add(x) -> Bool`(새로 넣었으면 `true`), `s.remove(x) -> Bool`, `s.clear()`, `s.freeze() -> Set<T>` |
| 고차 함수 | `each`, `any`, `all`, `fold`, `find`는 삽입 순서로 호출한다(3.12의 보장과 같다). `filter`는 `Set`을, **`map`은 `List`를** 돌려준다. `map` 결과가 겹칠 수 있어서, 중복을 버리려면 `.to_set()`을 명시한다 |
| 연산자 | 연산자 오버로딩이 없으므로 `|`, `&`, `-` 대신 위 메서드를 쓴다 |
| JSON | 배열(삽입 순서). 디코드할 때 중복 원소가 있으면 에러 |

#### `Dec` (10진수)

- **임의 정밀도 10진수**다. 돈, 세율처럼 10진 자릿수가 정확해야 하는 값에 쓴다.
- 리터럴: `12.30d`. 문자열에서 만들 때는 `Dec.parse("12.30") -> Result<Dec, ParseError>`를 쓴다.
- `+`, `-`, `*`는 정확하다. 결과의 자릿수(scale)는 덧셈·뺄셈이 두 피연산자 중 큰 쪽, 곱셈이 두 자릿수의 합이다.
- **`/` 연산자는 쓸 수 없다**(`E1206`). 나눗셈은 몫이 무한 소수가 될 수 있으므로 자릿수와 반올림을 명시한다: `a.div(b, scale: 2, round: Round.HalfEven)`. 0으로 나누면 결함 `R0103`이다.
- 반올림은 `x.round(scale: 0, round: Round.HalfUp)`처럼 쓴다. `Round`는 `HalfEven`, `HalfUp`, `Down`(0 방향 버림), `Floor`, `Ceil`이다.
- `==`와 정렬은 **수치로** 비교한다. `1.0d == 1.00d`는 참이고 해시도 같다. 자릿수 표현은 `x.scale()`과 출력에서만 다르다.
- `Int`, `Float`와 섞어 연산하면 에러다. 변환은 `n.to_dec()`, `d.to_float()`, `d.trunc_int()`처럼 명시한다.

#### `Bytes`

- **불변 바이트 열**이다. UTF-8이 아닌 데이터와 바이너리 파일에 쓴다.
- `b.len()`은 바이트 수, `b[i]`는 0~255의 `Int`다(범위 밖이면 결함 `R0102`). `b.slice(start, end)`도 바이트 단위다.
- 문자열과의 변환: `s.to_bytes()`(항상 성공), `b.to_str() -> Result<Str, Utf8Error>`.
- 만들기: `Bytes.from_list([0, 255])` (255를 넘는 값은 결함 `R0101`), `fs.read_bytes(path)`.
- `Str`과 달리 `b[i]` 인덱싱을 허용한다. 바이트 단위가 명확하고 O(1)이기 때문이다.

#### `Instant`, `Duration`

- `Instant`는 UTC 기준 시각이다(나노초 정밀도). `time.now() -> Instant !time`.
- `Duration`은 시간 길이다(부호 있는 정수 나노초, 약 ±292년). 만들기: `Duration(ms: 500)`, `Duration(s: 3)`처럼 단위 하나를 이름 붙은 인자로 준다.
- 연산은 메서드로 한다: `t.add(d)`, `t.sub(d)`, `t2.since(t1) -> Duration`, `d1.plus(d2)`, `d.times(3)`. 넘치면 결함 `R0101`이다.
- 출력 형식: `Instant`는 RFC 3339 UTC이고, 나노초가 0이면 소수부를 생략하고 아니면 뒤의 0을 지운다(`2000-01-01T00:00:00Z`, `…:00.5Z`). `Duration`은 `1.5s`, `250ms`, `-3m0s`처럼 가장 큰 단위부터 쓴다(Go의 형식과 같다). JSON 형식은 3.7을 따른다.
- 지역 시간대, 달력 계산(월 더하기 등)은 v0에 없다.
- 테스트에서 `time.now()`는 고정 시각 `2000-01-01T00:00:00Z`이다(3.13 규칙 9).

#### 문자열 보간에 쓸 수 있는 타입

- `{ }` 안에는 아무 식이나 쓸 수 있고, 문자열 리터럴도 넣을 수 있다: `"{name ?? "-"}"`. 중괄호 자체를 쓰려면 `\{`, `\}`로 쓴다.
- `"{x}"`에는 **`Int`, `Float`, `Dec`, `Bool`, `Str`, `Instant`, `Duration`**만 쓸 수 있다(`E1208`). `T?`, 컬렉션, `data`, enum은 보간 규칙이 모호하므로 변환을 명시한다: `"{xs.len()}"`, `"{name ?? "-"}"`.
- 디버그용 문자열이 필요하면 `debug(x) -> Str`을 쓴다(3.8의 디버그 표현). 형식은 안정성을 보장하지 않는다.

#### 표준 오류 타입

```pinion
enum FsError {
  NotFound(path: Str)
  PermissionDenied(path: Str)
  IsDirectory(path: Str)
  InvalidUtf8(path: Str)
  Other(path: Str, msg: Str)
}

enum JsonErrorKind {
  Syntax
  UnknownField
  MissingField
  DuplicateKey
  DuplicateElement
  TypeMismatch
  OutOfRange
}

data JsonError {
  pub kind: JsonErrorKind
  pub path: Str     // 예: "$.items[2].name"
  pub msg: Str
  // pub fn code() -> Str: "unknown_field"처럼 kind를 snake_case 문자열로 돌려준다
}

enum ParseError {
  InvalidFormat(input: Str)
  OutOfRange(input: Str)
}

data Utf8Error {
  pub byte_offset: Int
}
```

- `Int.parse(s)`, `Float.parse(s)`, `Dec.parse(s)`는 `Result<_, ParseError>`를 돌려준다.

#### 타입 이름으로 부르는 함수

- `Int.parse`, `Dec.parse`, `Bytes.from_list`처럼 **타입 이름으로 부르는 함수는 표준 내장 타입에만** 있다.
- 사용자 정의 타입에는 이런 함수(정적 메서드)를 만들 수 없다. 대신 같은 모듈의 `pub fn` 팩토리를 쓴다(3.6). 같은 일을 하는 방법을 하나로 두기 위해서다.

#### v0에 넣지 않는 자료형

| 자료형 | 이유 |
|---|---|
| 크기가 정해진 정수 (`Int32`, `UInt8` 등) | 대부분 `Int`로 충분하다. 바이트는 `Bytes`로 다룬다. Go 연동(v0 이후)에서 필요해지면 추가한다 |
| `Char` | 문자 단위는 "코드 포인트 하나짜리 `Str`"로 통일했다. 두 가지 방법을 두지 않기 위해서다 |
| 정렬된 맵·집합 (`SortedMap`, `SortedSet`), 덱(`Deque`), 힙 | 쓰임이 좁다. 필요하면 표준 라이브러리 확장으로 추가한다 |
| 지역 시간대, 날짜(`Date`) | 규칙이 복잡하다. v0 이후에 별도로 설계한다 |

### 3.16 클로저

- 클로저는 바인딩을 값으로 캡처한다. `data`는 값이 복사되고, `class`는 참조가 복사된다.
- 캡처한 `var`에 클로저 안에서 대입하면 `E3102`다.

### 3.17 모듈, import, 가시성

- **파일 하나가 모듈 하나다.** 프로젝트 루트는 `pinion.toml`이 있는 디렉터리이고, 소스는 `src/` 아래에 둔다.
- 모듈 경로는 `src/`부터의 상대 경로에서 확장자를 뺀 것이다: `src/todo/store.pi` → `todo/store`.
- `import todo/store`로 가져오고 **항상 마지막 경로 이름으로 한정해서** 쓴다: `store.load(...)`, `store.Todo`. 이름이 겹치면 `import todo/store as ts`. 이름만 골라 가져오는 import는 없다.
- 표준 라이브러리는 `import std/fs`처럼 가져온다. 기본 제공(prelude)은 기본 타입, `Ok`·`Err`·`Some`·`None`, `print`, `assert`뿐이다.
- **순환 import는 금지**한다(`E1601`).
- 가시성은 두 단계뿐이다. `pub`은 다른 모듈에 공개하고, 표시가 없으면 **같은 파일 안에서만** 보인다. 필드와 메서드도 같다.
- 3.6의 "모듈 밖"은 "다른 파일"을 뜻한다.

### 3.18 애너테이션

v0에는 애너테이션이 없다. 나중에 도입하더라도 컴파일러가 아는 고정 목록만 허용한다.

### 3.19 주석

- `//`는 줄 끝까지 이어지는 일반 주석이다. 문자열 리터럴 안의 `//`는 주석이 아니다.
- `///`는 **바로 다음 선언**에 붙는 문서 주석이다. 최상위 선언, 필드, 메서드, interface 메서드, enum 변형에 붙일 수 있다. 붙을 선언이 없는 `///`는 경고 `W0201`이다.
- v0에는 블록 주석(`/* */`)이 없다. **주석으로 컴파일 동작을 바꾸는 지시문도 없다.**
- 주석은 실행 의미에 영향을 주지 않는다.
- `pinion fmt`는 주석의 내용과, 문서 주석이 붙은 선언과의 연결을 보존한다.
- `pinion outline`은 문서 주석을 시그니처와 함께 보여준다. 타입만으로 드러나지 않는 의도, 단위, 제약을 본문을 열지 않고 알 수 있게 하기 위해서다.
- **문서 주석은 설명이지 계약이 아니다.** 컴파일러는 문서 주석의 내용을 검증하지 않는다.
- 적합성 예제의 `//#`, `//~` 표시는 테스트 하네스가 읽는 것이며, 컴파일러에게는 일반 주석이다.

```pinion
/// 주문 총액을 원 단위로 반환한다.
/// 할인액이 주문액보다 크면 0을 반환한다.
pub fn total(o: Order) -> Int {
  (o.subtotal() - o.discount()).max(0)
}
```

### 3.20 스크립트 모드

짧은 프로그램에서 `fn main`과 효과 선언을 쓰지 않게 한다.

- 단일 파일 프로그램(또는 프로젝트의 진입 파일 `src/main.pi`)에 **`fn main`이 없고 최상위 문(식, `for`, `while`, `if`, 대입, `assert` 등)이 하나라도 있으면** 스크립트다. 최상위 문과 최상위 `let`/`var`가 **소스 순서대로** 암묵적 `main`의 본문이 된다.
- 스크립트의 최상위 `let`/`var`는 **보통 지역 변수**다. Frozen 제한(`E1403`)과 최상위 `var` 금지(`E1404`)가 적용되지 않고, 패턴(`let (a, b) = ...`)과 `let ... else`도 쓸 수 있다. 그 대신 같은 파일의 함수에서는 보이지 않는다(함수는 인자로 받는다).
- 암묵적 `main`의 효과는 **추론한다**(선언하지 않는다). `pinion outline`이 추론한 효과를 `fn main() !io !fs`와 `effect upper bound`로 보여 준다. 반환 타입은 `()`이므로 `?` 대신 `else`·`??`로 실패를 다룬다.
- `fn main`이 있는 파일의 최상위 문, 진입 파일이 아닌 모듈의 최상위 문은 `E0001`이다. 함수·타입·테스트 선언은 스크립트 안 어디에나 둘 수 있다.
- 최상위 문이 없는 파일(선언만 있는 파일)은 지금까지와 같다. 스크립트 모드는 효과 검사를 끄지 않는다: 이름 있는 함수는 여전히 효과를 선언한다.

### 3.21 `std/http`

백엔드 코드의 가장 흔한 형태(JSON HTTP API)를 짧게 쓰게 한다. API는 STDLIB.md에 있다.

- 효과 `!net`. `app.listen(port)`만 `!net`이다. 경로 등록(`app.get(path, h)` 등)은 표준 고차 함수처럼 **핸들러 클로저의 효과를 그대로 전달**한다(3.13 규칙 5). 그래서 핸들러가 `fs`를 쓰면 등록하는 함수(보통 `main`)가 `!fs`를 선언한다.
- 경로 패턴은 `/`로 나눈 세그먼트이고 `:name`은 매개변수다(`req.params`). 맞는 경로가 여럿이면 **글자 그대로인 세그먼트가 많은 쪽**이 이기고, 같으면 먼저 등록한 쪽이다. 경로가 없으면 404 `{"error":"not found"}`, 경로는 있는데 메서드가 없으면 405 `{"error":"method not allowed"}`다.
- `Request`와 `Response`는 `data`다(불변, `==`, JSON). 헤더 이름은 소문자로 바꾼다. 쿼리는 경로의 `?` 뒤를 풀어서 `req.query`에 둔다(같은 키는 처음 값). `req.json<T>()`·`resp.json<T>()`은 본문을 `json.decode<T>`로 읽는다(타입 인자를 쓴다).
- **핸들러는 직렬로 실행한다**(프로세스 전체에 잠금 하나). 핸들러가 캡처한 `class` 상태와 `MutList`·`MutMap`을 두 요청이 동시에 만지지 않으므로 데이터 경쟁이 없다는 보장이 유지된다. 동시 처리는 6.3에서 다룬다.
- 테스트는 밀폐된다: 네트워크가 없고 `app.listen`은 `R0109`다. `app.handle(http.request("GET", "/books/1"))`로 네트워크 없이 같은 라우팅을 실행한다. 핸들러 안의 결함은 서버 전체를 결함 종료(종료 코드 70)시킨다. 포트를 열지 못하면 `error: listen: ...`을 표준 오류에 쓰고 종료 코드 1이다. 프로그램이 출력하지 않으면 서버도 아무것도 출력하지 않는다.

```pinion
import std/http

let app = http.App()
app.get("/books/:id", req => {
  let id = Int.parse(req.params.get_or("id", "")).ok() else { return http.error(400, "bad id") }
  http.json(Book(id: id, title: "Dune"))
})
app.listen(8080)
```

## 4. 예시: 주문 상태와 할인 규칙

> 설명용 예제다. `Item`, `Payment`, `Order`, `Event`, `FlowError`의 정의는 생략했다. 그대로 컴파일되는 예제는 `spec/conformance/`에 있다.

```pinion
type Cents = Int

enum OrderState {
  Cart(items: List<Item>)
  Paid(items: List<Item>, payment: Payment)
  Shipped(tracking: Str)
  Cancelled(reason: Str)
}

interface Discount {
  fn amount(o: Order) -> Cents
}

data Coupon : Discount {
  code: Str
  off: Cents

  fn amount(o: Order) -> Cents {
    if o.coupon == self.code { self.off } else { 0 }
  }
}

class Checkout {
  discounts: List<Discount>

  pub fn total(o: Order) -> Cents {
    let off = self.discounts.map(d => d.amount(o)).sum()
    o.subtotal() - off
  }

  pub fn next(s: OrderState, e: Event) -> Result<OrderState, FlowError> {
    match (s, e) {
      (Cart(items), Pay(p))             => Ok(OrderState.Paid(items, p))
      (Paid(_, _), Ship(t))             => Ok(OrderState.Shipped(t))
      (Cart(_) | Paid(_, _), Cancel(r)) => Ok(OrderState.Cancelled(r))
      _                                 => Err(FlowError.Invalid(s, e))
    }
  }
}
```

`Checkout`은 `class`라서 `List<Discount>`를 필드로 가질 수 있다. 같은 필드를 `data`에 두면 `E1401`이다.

## 5. 진단, 런타임 진단, 테스트 실행

### 5.1 진단 JSON

`pinion check --json`의 출력 형식에는 스키마 버전이 붙는다.

```json
{"schema": "pinion.diag/1",
 "diagnostics": [{
   "code": "E2001", "severity": "error",
   "file": "src/order.pi", "range": {"start": [31, 5], "end": [36, 6]},
   "msg": "match not exhaustive: missing Shipped, Cancelled",
   "fixes": [{
     "kind": "scaffold", "title": "add missing arms",
     "file_hash": "sha256:3f2a...",
     "edits": [{"range": {"start": [35, 40], "end": [35, 40]},
                "text": "\n    Shipped(t) => todo()\n    Cancelled(r) => todo()"}]
   }]
 }]}
```

- 위치는 `[줄, 열]`이고 1부터 센다. 열은 유니코드 코드 포인트 단위다.
- `file_hash`가 현재 파일과 다르면 도구는 수정을 적용하지 않는다.
- 수정 제안의 `kind`는 세 가지다. **`auto`는 두 가지를 모두 보장할 때만 붙인다: ① 런타임 동작이 같다 ② `pub` API와 타입 계약이 같다.**

| kind | 의미 | 예 |
|---|---|---|
| `auto` | ①과 ②를 모두 보장하므로 기계가 바로 적용해도 된다 | 비공개 함수의 쓰지 않는 효과 제거(`W3002`), 포맷 |
| `review` | 동작이나 계약이 바뀔 수 있어서 검토가 필요하다 | **`pub` 함수의 쓰지 않는 효과 제거**(공개 시그니처가 바뀜), 빠진 효과 추가(호출자에게 전파됨), `??` 괄호 추가(해석을 하나 고름), `let _ =` 추가(오류를 버림) |
| `scaffold` | 구현을 채워야 하는 골격이다 | 빠진 match 갈래에 `todo()` 삽입 |

비공개 함수에서 효과를 지우면 타입이 좁아질 뿐이라 컴파일 에러는 새로 생기지 않는다. 다만 호출자에게 새 `W3002` 경고가 생길 수는 있다.

### 5.2 런타임 진단

- 기본 출력: 코드, 위치, 메시지, **함수 이름만 담은** 호출 스택. **값은 캡처하지 않는다.** CLI도 실제 데이터와 인증값을 다룰 수 있기 때문이다.
- `pinion run --snapshot`이나 `PINION_SNAPSHOT=1`을 주면 `self`와 인자의 디버그 표현(3.8)을 함께 출력한다.
- `pinion test`에서는 **실제 효과를 선언하지 않은 테스트에만** 스냅샷을 기본으로 켠다. 이런 테스트는 기본 가짜 효과(3.13 규칙 9) 위에서만 돌기 때문에, 값이 실제 파일, 환경변수, 입력에서 올 수 없다.
- `!fs`처럼 실제 효과를 선언한 테스트는 스냅샷이 기본으로 꺼진다. `--snapshot`을 주면 켤 수 있다.

```json
{"schema": "pinion.runtime/1", "code": "R0102", "file": "src/cart.pi", "at": [14, 5],
 "msg": "index out of range: 3 >= 3",
 "stack": ["src/cart.pi:14:5 Cart.remove", "src/main.pi:8:3 main"],
 "snapshot": {"self": {"class": "Cart", "items": ["a", "b", "c"]}, "args": {"index": 3}}}
```

### 5.3 테스트 실행 정책

- 테스트는 파일 순서대로 **하나씩 순차 실행**하고, **테스트마다 별도 프로세스**에서 돌린다. 결함, 스택 오버플로, 무한 루프가 다른 테스트에 영향을 주지 않는다.
- 효과는 기본으로 가짜 구현이다(3.13 규칙 9). 실제 효과는 테스트에 선언한 것만 쓴다.
- `assert`가 실패하면 그 테스트는 그 자리에서 멈추고 `failed`(`T0001`)로 기록된다.
- 결함이 나면 그 테스트는 `aborted`(`T0002`, 원인 `R` 코드 포함)로 기록된다.
- 테스트당 제한 시간은 기본 10초이고, 넘기면 `timeout`(`T0003`)이다.
- 어느 경우든 **나머지 테스트는 계속 실행**한다. 하나라도 통과하지 못하면 종료 코드 1이다.
- `pinion test --json`의 출력 형식은 `pinion.test/1`이다.

### 5.4 탐색 도구

`pinion outline`은 문서 주석, 시그니처, 효과, `mut`, 각 `_`가 흡수하는 조합(패턴으로 압축), `main`의 효과 상한을 보여준다.
v0 이후: `pinion query callers|impls|uses`, `pinion trace`

## 6. v0 이후 확장 (방향만 기록)

### 6.1 보안: 막는 범위를 정확히 적는다

| 장치 | 막는 것 | 막지 못하는 것과 보완할 점 |
|---|---|---|
| `sql"... {x}"` | 값이 쿼리 구조를 바꾸는 SQL 인젝션 | 동적 테이블명, 정렬 컬럼, 조건 조합은 따로 안전한 표현(식별자 허용 목록, 쿼리 빌더)이 필요하다. 드라이버별 placeholder 차이는 SQL 계층이 흡수한다 |
| HTML 기본 이스케이프 | HTML 본문 문맥의 XSS | 속성, URL, JavaScript, CSS 문맥은 문맥별 이스케이프 규칙이 따로 필요하다 |
| `Req<Body>` | 형식과 스키마가 틀린 입력 | 권한과 업무 규칙 검증은 하지 않는다 |
| `Secret<T>` | 타입이 유지되는 동안 로그, 디버그, JSON, 스냅샷으로 새는 것 | `.expose()` 이후의 값은 보장하지 않는다 |
| lockfile 해시 | 같은 버전의 패키지 내용이 바뀌는 것(무결성) | 처음부터 악성인 패키지는 막지 못한다. 게시자 검증, 허용 목록, 효과 제한을 따로 둔다 |
| 계약 `requires`·`ensures` | 개발 중에 내부 가정이 깨지는 것 | **외부 입력 검증에는 쓰지 않는다.** 외부 입력은 항상 실행되는 코드로 검증한다 |

### 6.2 정확성
`Id<T>`(ID 타입 구분), `db.tx { }`(트랜잭션), 계약

### 6.3 동시성
- 효과와 분리해서 설계한다. 순차 호출을 기본으로 하고, 명시적인 작업 생성·대기(`spawn`, `await`)와 구조적 스코프를 쓴다.
- 작업 사이에는 Frozen 값만 넘길 수 있다. `class`와 `Mut*`를 넘기는 것은 소유권 규칙을 구현한 뒤에 허용한다. **"데이터 경쟁 없음"은 이 범위 안에서만 약속한다.**

### 6.4 capability, 아키텍처 규칙, 운영
- capability: `pinion.toml`에서 효과별 자원 범위를 정하고 런타임이 강제한다.
- 아키텍처 규칙: 모듈 의존 규칙, `pinion api diff`, edition
- 운영: 구조화 로그, OpenTelemetry, 감사 로그

## 7. Go 백엔드

### 7.1 구조

```
.pi ─▶ 파싱 ─▶ AST ─▶ 이름 해석·타입·속성·효과 검사 ─▶ 검사된 중간 표현(IR) ─▶ Go 생성 ─▶ go build
```

Pinion의 의미는 IR 단계까지에서 확정한다. Go 생성기는 IR을 옮기기만 한다.

**v0 구현 노트 (2026-11-20)**: v0 컴파일러는 검사기와 코드 생성기를 분리해서 병렬로 만들기 위해, 정적 검사를 통과한 AST에서 **동적 값 모델**(런타임의 범용 `Value`)로 Go 코드를 생성한다. 언어 의미는 같고, 차이는 실행 성능뿐이다(Go 네이티브 타입보다 느리다). 타입 정보를 쓰는 생성(네이티브 Go 타입)은 v0 이후 최적화 과제로 둔다.

### 7.2 Go가 주는 것과 Pinion이 직접 구현할 것

Go의 interface와 합성 중심 모델은 Pinion의 객체 모델과 잘 맞는다. 다음은 Go에 없으므로 Pinion 컴파일러와 런타임이 직접 구현한다.

- enum과 match 완전성 (Go에서는 sealed interface로 표현)
- 타입 속성(Frozen, Eq, Ord, Hash, Encode, Decode) 계산, `mut` 검사, 효과 검사
- 구조적 `==`, 순서와 무관한 `Map` 비교와 해시, 삽입 순서를 지키는 `Map`, JSON 매핑, 디버그 표현
- 오버플로 검사 정수 연산, 유한성 검사 Float 연산
- 결함 중단, 런타임 진단, `//line` 지시문을 이용한 `.pi` 위치 연결
- 테스트 프로세스 격리와 효과 대체

### 7.3 Go 연동 경계 (`extern`, v0 이후)

| 문제 | 대응 | 한계 |
|---|---|---|
| `nil` 반환 | 래퍼가 검사해서 `T?`나 `Err`로 변환 | nil 슬라이스가 "빈 결과"인지 "오류"인지는 바인딩마다 계약으로 정한다 |
| `panic` | 래퍼가 `recover()`로 `Err(GoPanic)`으로 변환 | `recover()`는 같은 goroutine의 panic만 잡는다 |
| 숨은 효과 | `extern` 선언에 효과를 적고 `pinion audit`가 import 그래프로 대조 | 효과 선언은 검증된 사실이 아니라 신뢰하는 계약이다 |
| 참조 공유 | 경계에서 복사 | 라이브러리가 원본을 동시에 바꾸면 복사 도중 경쟁이 생길 수 있다 |
| 정수 오버플로 | 반환값 범위 검사 | 라이브러리 내부에서 이미 일어난 오버플로는 찾을 수 없다 |
| 민감 정보 | `Secret`은 `.expose()` 없이 넘길 수 없음 | `err.Error()`, `fmt.Sprint(r)` 메시지에도 민감한 값이 들어갈 수 있다 |

신뢰 등급: `std` > `verified` > `unsafe extern`(`ffi/` 모듈에서만 허용, audit 보고서에 노출)

## 8. 성공 측정: PinionBench

| 평가 | 질문 | 방법 |
|---|---|---|
| **제품 평가** | 실제 개발 환경 전체에서 Pinion의 비용이 낮은가 | 각 언어의 실제 도구와 생태계를 포함해 전체 작업 비용을 비교 |
| **원인 분석** | 무엇이 효과를 냈는가 | 문서와 도구 조건을 통제하거나, Pinion 기능을 하나씩 빼고 비교 |

측정 규칙:
- 모델 버전, 설정, 작업 예산을 고정하고 과제마다 여러 번 실행한다.
- Pinion 가이드와 도구 응답도 토큰 비용에 포함한다.
- 실제로 읽은 토큰과 바이트를 잰다.
- 컴파일 통과와 기능 테스트 통과를 따로 기록한다.
- 숨겨진 테스트와 수정 후 회귀 테스트를 둔다.
- 실패한 과제까지 포함한 "성공한 과제 하나당 비용"을 계산한다.

초기 과제 약 20개는 어떤 유형의 작업에서 이득이 생기는지 찾는 용도로 쓴다.

### 8.1 실제 작성 비용으로 재검토할 규칙

v0에서 일관성을 위해 엄격하게 둔 규칙은 측정 결과를 보고 다시 판단한다.

| 규칙 | 측정할 것 |
|---|---|
| `E3105` (필드 대입은 자기 `mut fn` 안의 `self.필드`로만) | `E3105` 발생 빈도와 이를 고치는 데 든 토큰·시도 횟수, 단순 대입을 감싸려고 추가한 setter 메서드 수, AI가 `pub mut`를 "외부에서 쓸 수 있다"로 오해한 빈도 |

## 9. 열린 질문

- `data` 필드에 담을 수 있는 "Frozen interface" (구현체가 모두 `data`인 interface)를 둘지
- interface 기본 메서드와 위임 문법 (벤치마크 결과를 보고 결정)
- 사용자 정의 고차 함수의 효과 다형성
- 한정 이름만 쓰는 import 규칙이 토큰을 너무 늘리지 않는지 (벤치마크로 확인)
- `data`의 자동 Ord, 튜플·`Result`의 JSON 매핑
- NaN을 허용하는 수치 계산용 Float 타입
- 테스트 병렬 실행
- 불변 컬렉션의 공변(`List<Coupon>` → `List<Discount>`) 허용 여부. 타입 안전성 문제는 없지만, Go에서는 변환할 때 복사 비용이 숨는다
- 비교 함수를 받는 정렬, grapheme 단위 문자열 연산

### 검토한 런타임 대안

- **Go (채택)**: interface와 합성 중심 모델이 잘 맞는다. 단일 바이너리, 메모리 안전, goroutine
- JVM: 엔터프라이즈 생태계가 가장 크다. 대신 런타임이 무겁다
- TS/Node: 웹 생태계가 강하다. 대신 npm 공급망 위험이 있고 CPU 작업은 단일 스레드에 묶인다
- Python: 데이터와 AI 생태계가 강하다. 대신 타입 보장과 성능이 약하다
